# PPT Implementation Status

This file maps the opening-presentation commitments to executable project artifacts.

| PPT item | Status | Implementation / decision |
|---|---|---|
| CT-RATE 3D CT, reports, labels, metadata | Implemented | `data/dataset`, `scripts/prepare_dataset.py`, `scripts/build_multimodal_manifest.py` |
| 6-8 frequent labels | Superseded | The system now uses the complete canonical CT-RATE 18-label registry in `chestct_agent/labels.py`. |
| CT resampling, windowing, slice rendering | Implemented | `chestct_agent/tools/ct_preprocess.py` |
| CT-CLIP / 3D CNN image baseline | Implemented with CT-CLIP | Official CT-CLIP v2 is used. A duplicate 3D CNN was not added because the PPT presents these as alternatives. |
| TF-IDF + Logistic Regression report baseline | Implemented | `scripts/train_text_classifier.py`; balanced 18-label one-vs-rest baseline. |
| BERT / lightweight LLM prompt baseline | Implemented with Qwen prompt | `scripts/evaluate_prompt_baseline.py`; real API calls only, fallback results are rejected for reporting. |
| RadGraph / RadGraph-XL report structure | Implemented with official RadGraph-XL | `report_graph_tool` runs Stanford AIMI `modern-radgraph-xl` in an isolated worker, outputs Anatomy/Observation entities and `modify`, `located_at`, `suggestive_of` edges, and feeds typed assertions into report evidence. A rule graph is retained only as an explicitly degraded fallback. |
| CT + report multimodal fusion | Implemented | Per-label calibrated score fusion and conflict detection in `consistency_checker.py`. |
| CT + report + RAG Agent output | Implemented | LangGraph workflow plus BM25, Qwen embedding, Qdrant, and Qwen reranker. RAG supports explanations but does not overwrite diagnostic scores. |
| Definitions, imaging findings, terms, cases | Implemented | 54 curated label-section documents plus CT-RATE similar-case retrieval. |
| Evidence sentence metrics | Implemented | `scripts/evaluate_report_evidence.py`; explicitly reported as a weak-label proxy, not manual span gold. |
| Retrieval Recall@k / MRR | Implemented | `scripts/evaluate_retrieval.py` also reports nDCG and latency. |
| JSON validity / hallucination / review rate | Implemented | Typed Pydantic schema, validator, approval gate, and `scripts/evaluate_agent.py`. |
| Real slice, bbox, mask evidence | Partially implemented honestly | RadGenome `lung nodule` / `lung effusion` are lesion masks; other labels use anatomy masks. Unverified normalized mapping is never called affine-aligned. |
| Dynamic Agent tools | Implemented | Qwen proposes an allow-listed plan; policy fills mandatory safety steps. |
| Memory, MCP, failure recovery, approval | Implemented | SQLite audit memory, FastMCP server, bounded retries/degradation, FastAPI approval endpoints. |
| Frontend, API, Docker | Implemented | Streamlit, FastAPI, `Dockerfile`, and validated `docker-compose.yml`. |
| Patient-level calibration / test split | Implemented | No reconstruction of one patient crosses splits; overlap is checked and reported. |
| Long-tail handling | Implemented for current baselines | Balanced text loss, per-label thresholds/calibration, effective-number/positive weights, per-label and macro metrics. |
| DRR-RATE fallback | Not needed | Native 3D CT-CLIP runs successfully on the RTX 4060 Laptop, so the fallback would reduce task fidelity. |
| M3D/M3D-LaMed | Reference only | CT-RATE and CT-CLIP already cover the scoped chest CT task; downloading another broad corpus would consume budget without fixing a current failure. |
| LlamaIndex | Replaced | Custom retrieval is smaller and exposes each BM25/dense/reranker score; LangGraph remains the orchestration layer. |
| LoRA / QLoRA challenge experiment | Deferred | The main 35B-A3B model is API-hosted and cannot be fine-tuned on this laptop. A smaller-model LoRA run would answer a different model question and is not presented as completed. |

The machine-readable experiment snapshot is generated by:

```powershell
python scripts/summarize_experiments.py
```
