# ChestCT-Agent 本周阶段汇报

日期：2026-07-27  
项目定位：课程演示原型，不用于临床诊断或治疗决策。

## 一、结论摘要

本周完成了两类关键工作：

1. 集成并验收了新版 Agent 的 CT 归因/专科工具能力，并保持既有的 CT-CLIP 证据到 Stage-2 结构化 JSON 输出链路。
2. 完成了“反馈提交—审核—候选校准—SFT 构建—候选 QLoRA—患者隔离冻结集回归门禁”的闭环验证。

第二项的候选 adapter 在冻结集上未通过门禁：召回率提高，但误报增加，使微平均 F1 从 **0.7682 降至 0.7515**。因此候选版本已明确标记为**不部署**，正式 Stage-2 adapter 保持不变。这是预期的安全行为，而不是线上模型被错误替换。

### 1. Agent 与 CT 证据能力

- 合并新版 CT attribution 和 specialist tools；Agent 可在受控工具白名单、重试/降级和输出校验的约束下工作。
- CT-CLIP 使用冻结的 `CT-CLIP_v2` zero-shot 推理，为 Stage-2 提供 8 个定量证据字段。
- 本地 CXR-BERT 加载路径兼容性已修正，离线环境不会因文本编码器缺失而尝试访问 Hugging Face。
- 已有端到端验收覆盖：CT 输入及受控报告 -> CT-CLIP -> Qwen3.5-9B + Stage-2 adapter -> 可解析的 Stage-2 JSON。

### 2. 反馈与候选再训练机制

- 新增反馈数据模型与 API：提交、待审核、批准、拒绝均有持久化审计记录；反馈提交保存原始响应快照，避免后续推理变化污染审核依据。
- 新增安全校准脚本：只生成候选统计，绝不自动改写线上阈值、adapter 或完整模型。
- 新增从 `approved` 反馈构建 Stage-2 SFT JSONL 的脚本，并以病例/患者标识做切分，防止训练和验证交叉。
- 新增模拟反馈和冻结评估清单脚本，用于在没有真实临床反馈的课程项目中验证工程流程。
- 新增维护脚本，可按日运行候选校准检查；仍必须经过固定回归集和人工批准才允许发布。

## 三、模拟反馈实验设计

目的不是证明模型临床提升，而是验证校准与发布门禁是否可靠。

| 项目 | 设置 |
| --- | --- |
| 原始样本 | 既有 Stage-2 100 例展示集 |
| 标签来源 | 隐藏的 CT-RATE 报告派生弱标签 |
| 反馈/冻结划分 | 患者级 60 / 40，零重叠 |
| 反馈事件 | 58 条：54 批准、4 拒绝 |
| 候选 SFT | 29 条，训练/验证 23/6 |
| 候选训练 | 从正式 Stage-2 adapter 继续 QLoRA，1 epoch、6 steps |
| 发布规则 | 冻结集微平均 F1 不下降，且 JSON/证据完整性不退化 |

**边界：**“反馈”是用隐藏弱标签模拟的，无法代替医生审核，且训练样本很小；实验只能说明系统闭环可运行。

## 四、冻结集结果与决策

冻结集 40 例完全不进入反馈数据库或候选训练。两版均输出 40/40 个有效 JSON，CT 证据字段均为 320/320 覆盖且数值一致。

| 指标 | 正式 Stage-2 adapter | 反馈候选 adapter | 变化 |
| --- | ---: | ---: | ---: |
| Micro Precision | 0.8788 | 0.7750 | -0.1038 |
| Micro Recall | 0.6824 | 0.7294 | +0.0471 |
| Micro F1 | 0.7682 | 0.7515 | **-0.0167** |
| True Positive | 58 | 62 | +4 |
| False Negative | 27 | 23 | -4 |
| False Positive | 8 | 18 | +10 |
| JSON 有效率 | 100% | 100% | 0 |
| CT 证据覆盖率/一致性 | 100% / 100% | 100% / 100% | 0 |

标签层面，肺实变/阴影 F1 上升（0.7407 -> 0.8387），但动脉壁钙化（0.6667 -> 0.4706）和冠脉壁钙化（0.6667 -> 0.5882）退化；其余多项持平。候选模型更激进地预测阳性，带来召回提升和大量额外误报。

**发布决定：拒绝候选 adapter，不覆盖正式 Stage-2 adapter。**

## 五、为何候选更新没有变好

- 有效训练样本仅 23 条、仅 6 个优化步，样本量远小于能稳定更新 9B 模型行为所需规模。
- 模拟反馈与原弱监督标签同源，新增信息有限，可能重复放大同一偏差。
- 反馈类别不均衡，动脉壁钙化、冠脉壁钙化等标签没有足够的纠错覆盖。
- 从现有 adapter 继续训练时，候选模型更倾向输出阳性，故漏报减少但误报增加。

这说明门禁设计是必要的：即使流程全部执行成功，也不能把“训练完成”当成“可以上线”。

## 六、当前可演示的功能

1. 输入 CT（NIfTI/DICOM ZIP）与受控报告，运行 CT-CLIP 并输出多标签证据分数。
2. 使用 Qwen3.5-9B + 正式 Stage-2 adapter 输出严格 JSON、中文解释和证据轨迹。
3. 展示 CT 归因/专科工具、RAG/相似病例、审计轨迹和输入输出校验。
4. 提交、审核反馈；从批准反馈生成候选 SFT 数据；运行候选校准和回归门禁。
5. 演示“候选退化被拒绝”的安全发布案例。

## 七、后续建议

- 课程答辩可直接展示：正式推理一次 + 提交反馈 + 审核 + 候选训练报告 + 冻结门禁拒绝结论。
- 若未来接入真实反馈，应由有资质人员审核，累积数百条以上且类别平衡的反馈；候选训练应混入原始 SFT、降低学习率并保持完全独立的患者级冻结集。
- 任何真实数据、报告正文和权重只在授权的本地/服务器环境保存；仓库仅保留来源说明、清单、哈希和可复现脚本。
